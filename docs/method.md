# 研究方法

## 移植已有方案，再找新问题（2026-11-16 确定）

Heddle 不以提出新机制为卖点，而是把成熟方案原样移植到 Linux 桌面，实测收益，并找出移植后才出现的新问题。贡献是这些新问题的实测证据、成因，以及最小修补和它的代价。

- 每个方案先按原样移植，不预先修补。同一套回放下同时记录收益（内存、CPU、启动或恢复时间）和损害（卡住、状态错误、任务失败、观测延迟）。
- 损害要对应到具体任务和原因。每个新问题给出触发条件、发生频率、最小修补和修补代价。
- 基线是现有的每任务一台桌面虚拟机。KSM、gVisor、CRIU 和自定义内核各自开启前单独征得同意。

| 已有方案（出处） | 移植到 Linux 桌面 | 可能的新问题（假设） |
|---|---|---|
| 共享内核的 GUI 容器（ReDroid、Anbox Cloud） | 桌面从虚拟机换成容器，分别在 runc、runsc、microVM 下运行 | 无 GPU 时软件渲染的 CPU 开销；Chromium 自带沙盒能否在 gVisor 中运行；应用假设存在的设备 |
| 静止后冻结（安卓 cached 应用、Lambda） | cgroup freezer 冻结整个桌面，观测前解冻 | 解冻后积压定时器集中触发；合成器未冻而应用被冻时被判为无响应；D-Bus 调用约 25 s 超时；IMAP 等长连接断开 |
| 快照克隆、写时复制（Firecracker、SnapStart） | 预热好的桌面做模板，克隆 N 份 | 身份重复：machine-id、随机数种子、D-Bus 认证信息、Chrome 配置锁（含主机名与 PID）；桌面写内存频繁，共享页很快失效 |
| 合并相同页（KSM） | 合并 N 个同类应用实例的相同页 | ASLR 与 JS 堆布局降低可合并比例；异构应用混部时更低 |
| 看不见就不渲染（安卓不可见 Activity、Chrome 后台标签限速） | 合成器只在截图时放行帧 | 应用卡住；截到旧画面；画面稳定的判定；截图延迟 |
| 每应用沙盒（安卓每应用 UID、Flatpak） | 每个 agent 一套命名空间 | 单实例应用；文件选择需要走 portal；跨应用任务的数据传递 |
| 杀进程后恢复（安卓低内存查杀加 savedInstanceState） | 内存紧张时回收桌面，需要时恢复 | Linux 应用不保存界面状态，只能外部 checkpoint；CRIU 对 Chromium、合成器、D-Bus 能否恢复 |
| 按截止时间调度（deflation、cgroup 权重） | 按下一次观测分配 CPU 份额 | 余波被压缩后截图时页面未加载完，任务成功率下降 |

为什么这些问题可能是 Linux 桌面特有的（判断）：安卓应用按"随时会被冻结、被杀"编写，会主动保存状态、停止渲染；serverless 快照的对象是无窗口、无长连接、无会话总线的函数。Linux 桌面应用默认自己持续运行、始终可见、独占机器。移植后出问题的地方，预期集中在这些前提上：可冻结、实例唯一、有人观看、会话持续。

## 负载

OSWorld 1.0 适合做"任务单元加正确性检查"：每个任务有评测器，可以逐个核对移植的方案把哪些任务做坏了。它的局限：

| 缺口 | 影响 |
|---|---|
| 会话短：每任务几分钟、约 30 次工具调用，从干净快照开始 | 测不到状态积累、长期内存增长、长连接超时；冻结的问题会被低估 |
| 没有到达过程、并发、空闲分布 | 无法回答同时有多少桌面、各自空闲多久 |
| 所有任务同一镜像 | 高估 KSM 合并与快照克隆的共享比例 |
| 部分任务依赖外网 | 结果不完全可复现 |
| 单 agent、无人在场 | 测不到多个 agent 与用户共用一个桌面 |

补充来源（只核对到摘要或二手资料）：[OSWorld 2.0](https://huggingface.co/papers/2606.29537) 有 108 个长周期工作流，平均约 318 次工具调用，网站自托管；[OS-Marathon](https://arxiv.org/html/2601.20650) 是长周期重复任务。没找到计算机使用 agent 的公开生产 trace，最接近的是 [GitHub Copilot 编码 agent 生产 trace](https://www.alphaxiv.org/abs/2608.00101)。

拟定的负载组合（提案）：

1. 正确性：OSWorld 1.0 加 OSWorld 2.0 的评测器。
2. 单桌面的时间节奏：回放 1.0 与 2.0 的轨迹；2.0 是否公开带时间戳的轨迹尚未确认。换桌面后坐标错位的问题见 [README](../README.md#step-0-workload-and-control)。
3. 规模：到达过程与会话长度借用 Copilot trace 的分布，混合不同应用与镜像。需说明这是从编码 agent 借来的假设。
